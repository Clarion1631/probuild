- The Drive job folders under `New Receipts & Checks/` stay. Dropping a file there still works.
- The archive `Processed Receipts/YYYY/MM/` stays and stays in Drive.
- The "Receipts Need Review" chat stays the place CJ and Richard answer questions and sign memos.
- QuickBooks still gets one Purchase per receipt with the PDF attached.

**Changes:**
- ProBuild owns the queue and the state. Drive is a drop box and an archive, not the brain.
- Gemini reads happen inside ProBuild, once, with the job's own phase list in the prompt.
- ProBuild creates the `Expense` row the moment the receipt is booked. No more waiting on the 4-hour sync for job cost to appear.
- Missing-receipt memos are generated by ProBuild from bank lines, sent as Chat cards, and auto-closed when the receipt shows up.
- All bot alerts stop going to Telegram and a personal inbox.

### Pipeline steps (all inside ProBuild)

1. **Intake** writes the row and stores the file in Supabase storage. Duplicate `sourceRef` returns the existing row. Done in under a second, so any caller can be fire-and-forget.
2. **Read** (cron every 5 min, or triggered): Gemini with the same prompt the Apps Script uses today, plus the project's estimate phases so it returns `suggestedCostCodeId`. Detects multi-receipt scans and non-receipts (payroll screenshots, statements) exactly as v3.6 does.
3. **Route**: no job → `NEEDS_JOB`; weak-dedup hit with a different total → `NEEDS_REVIEW`; strong-dedup hit with same total → `DUPLICATE`.
4. **Book**: reuse the existing `qbo-receipts/create` core with a 20 s fetch timeout and a retry queue. No email fallback. When Intuit is down (like today) rows wait in `BOOKING` with a visible reason, then drain. This removes the "MAYBE in QuickBooks" class of alert entirely.
5. **Cost**: create `Expense` with `projectId`, `costCodeId`, `taxAtSource`, `receiptUrl`, `qbPurchaseId` in the same transaction as the booking record. The 4-hour QBO sync stays as reconciliation only (it will find the row already exists by `qbPurchaseId`).
6. **Archive**: copy to Drive `Processed Receipts/YYYY/MM/` with the v1 filename convention, and remove the original from the drop folder. Marge's archive keeps working unchanged.

- **Chat**: `sweepChatReceipts` likewise forwards photos posted in Receipts Need Review to intake with `source=chat` and the thread id, so a reply photo closes the matching memo.
- **Web**: `/receipts/new` in ProBuild. Drag a file, pick a job, done. Rare, but it exists.

### Missing receipts without a chaser

- Nightly: for each `BankLine` (from the QBO bank feed) older than 3 days with no matching `Expense` (amount + date ± 2 days + payee), create a `ReceiptRequest` owned by the card holder (…8516 = CJ, …6098 = Richard).
- Post ONE card per owner per day in Receipts Need Review listing their open items with three replies: "photo attached", "job is X", "sign memo". The memo signature is the existing chat sign flow (the one that works for Richard). Email PDFs are never sent.
- When an intake row later matches the bank line, the request auto-closes and the card updates. This is the bug that produced today's "7 memos" list: nothing closed a memo when the receipt arrived.
- Marge sees all of it on the queue page; she stops keeping a separate tracker.
